# 多模态融合方法（M4）

> 本文说明 SiteGuard 视觉通路与图文融合的设计与实现，对接《02-架构与技术选型》§2
> 图像检测选型行（YOLO 系 + SHWD，加分项、离线推理、M4 引入，可选依赖）与
> 《03-模块详设》§1 条目卡 schema（`merged_from` 字段纪律：多模态融合后回填）。
> 风格对齐《kg-构建方法.md》。

## 1. 设计定位：融合 = 条目卡的对齐合并

系统唯一的中间表示是**隐患条目卡 HazardCard**（plan/03 §1）：文本规则抽取、LLM 兜底、
图像检测三类通路都产出同一结构，后续条款关联/风险分级/建议生成/入图只认条目卡。
因此图文融合不引入任何新表示——就是**两类条目卡按对齐键的受控合并**。

视觉卡与文本卡的字段约定：

| 字段 | 文本卡（rules/llm） | 视觉卡（vision） |
| --- | --- | --- |
| extractor | `rules` / `llm` | `vision` |
| quote | 日志原文摘录（子串可校验） | `图像 <文件名> 检出：<隐患名>` |
| attrs | 数值槽位（height_m 等） | `bbox`（像素坐标）+ `detection_class` |
| evidence | `record_index` | `image`（文件名）+ `bbox` |
| confidence | 规则通路固定 0.95 | 检测器置信度（0~1） |
| site_object | 词表部位 | 词表条目 `site_objects[0]`（部位推导，见 §2） |

## 2. 视觉通路（siteguard/extract/vision.py）

### 2.1 图像来源与台账

- 来源：**SHWD（Safety Helmet Wearing Dataset）官方仓库**
  `njvisionpower/Safety-Helmet-Wearing-Dataset`（GitHub API 直连核验，2026-09-27，
  LICENSE: MIT；数据集本体 7581 张经百度网盘分发，**不入仓**）。
- 按台账纪律抽样 2 张小图入仓（`data/samples/images/shwd_3.jpg`、`shwd_5.jpg`，
  55 KB / 130 KB），逐张登记来源路径、许可、sha256、脱敏检查结论于 `data/README.md`
  images 行；其余 8 张候选因非施工场景（1/9/10）、第三方水印（2）、可识别人脸或
  公众人物（4/6/7/8）排除，台账留痕。`.gitignore` 同步放行 `shwd_*.jpg`。

### 2.2 检测接口与可注入依赖

沿用 M3 `kg/visualize.export_html(…, pyvis_mod=None)` 的可注入依赖范式，**import 期
零硬依赖** torch/ultralytics（只进 pyproject optional 组 `vision`）：

```python
detect(image_path, model=None, detector=None, schema=None) -> (list[HazardCard], warnings)
collect_vision_cards(image_paths, schema=None, detector=None, model=None) -> (cards, warnings)
load_model(model=None) -> (model_or_None, warnings)
```

- `model`：已加载模型实例 / 权重路径（或环境变量 `SITEGUARD_VISION_MODEL`）；
- `detector`：`image_path -> list[{class_name, bbox, confidence}]`，**仅供测试与扩展注入**
  （fake 检测器只在 tests/test_m4.py 注入并标注，禁止编造"检出"进真实报告）；
- 真实推理：`model.predict(image_path, conf=0.25)`，`Results.boxes` 解析为统一
  detection dict；权重由 SHWD 官方通道微调产出自备（M4 不随仓库分发权重）。

### 2.3 检出类别 → 受控词表映射

检测结果按**类别名**映射到受控词表（`data/knowledge/seed/hazard_types.json`），
不得硬编码未登记 id：

| SHWD 类别名 | 语义 | 映射 |
| --- | --- | --- |
| `helmet` | 已佩戴安全帽 | 合规，不生成卡 |
| `head`（及 `no_helmet` 等别名） | 未戴帽人头 | `未佩戴安全帽`（HT-GCZY-007） |
| 其他任何类别 | — | warning + 丢弃（词表缺条目须走受控流程补登记） |

词表缺"未佩戴安全帽"条目，按受控流程补登记（M4）：`HT-GCZY-007`（高处作业，较大风险）
+ 措施 `ME-GCZY-007` + 规则库 `RL-GCZY-007`（与词表一一对应纪律），`verify_seed_data`
校验通过，`datagen --force` 生成产物位级一致（新条目不在演示语料模板内）。
**条款依据留空**：条文库 54 条暂无可挂安全帽的官方核验条款（JGJ 扩充受通道限制，
见台账"待核验清单"），不编造条文，`clause_refs: []`，研判报告该类卡显示"无条款"。
"反穿衣/反光背心"类同（SHWD 标注本身不含该类），待词表受控扩充后接入。

视觉卡 `site_object` 取词表条目 `site_objects[0]`（HT-GCZY-007 → `外脚手架`），
作为与文本卡对齐的部位键。

## 3. 图文融合规则（merge_cards）

```python
merge_cards(text_cards, vision_cards, time_window=60) -> (cards, warnings)
```

对齐键与合并动作：

1. **必要条件**：`site_object` 相等（非空）且 `hazard_type_id` 相等。
   不同隐患类型、不同部位**一律不合并**；
2. **时间窗**：仅当两侧均有可解析时间（`attrs["time"]`，`HH:MM[:SS]`，当日分钟数）
   时施加约束 `|Δ分钟| <= time_window`（默认 60 分钟，**含边界**）；任一侧缺时间或
   不可解析则不施加（当前文本通路不产出时间属性，该约束对视觉侧扩展预留）；
3. **合并动作**（保留文本卡为主体）：
   - `merged_from` 回填：双方合并去重保序，文本卡 `["rules"]` × 视觉卡 `["vision"]`
     → `["rules", "vision"]`（语义即 text/vision 双源，取 extractor 名与
     既有数据一致）；
   - `confidence` 取双方较高值；
   - `evidence` 合并保留双方出处：文本 `record_index` 保留在顶层，视觉证据收进
     `evidence["vision"]` 列表（`image`/`bbox`/`confidence`，多次融合自然追加）；
   - `attrs` 合并（文本键优先，视觉补充 `bbox`/`detection_class`）；`quote`/`source`
     保留文本主出处；
4. **未命中的视觉卡**原样保留（`merged_from=["vision"]`），独立走研判；
5. **不带视觉输入**（`vision_cards` 为空）：原样返回 `text_cards`（同一对象），
   零 warnings——纯文本通路行为逐位不变（验证见 §6）。

融合发生在条目卡统一编号（`HC-xxxxx`）之前，融合卡与独立视觉卡同文本卡一样经过
条款关联 → 风险分级 → 建议生成，判断结构无差别。

## 4. 置信度与 human_confirm

风险分级引擎既有纪律（`reasoning/risk_level.judge`）：
`human_confirm = confidence < 0.6 or extractor == "llm"`。

- 视觉卡置信度即检测器置信度：低置信检出（如 0.3）研判后自动进入报告
  "待人工确认"单列；
- 融合卡 confidence 取高后，通常不再触发人工确认；独立视觉卡按自身置信度判定；
- 该阈值与 LLM 兜底卡一致，报告渲染无需区分来源。

## 5. 降级矩阵（全部不崩溃，exit 0）

| 场景 | 触发 | 行为 |
| --- | --- | --- |
| 主动禁用 | `SITEGUARD_DISABLE_VISION=1`（或 settings `disable_vision`） | 空卡 + warning"视觉通路已禁用" |
| 图像缺失 | 文件不存在 | 空卡 + warning"图像不存在" |
| 坏图 | 非 JPEG/PNG 魔数、过小、不可读（stdlib 魔数检查，不依赖 PIL） | 空卡 + warning |
| 缺依赖 | 无 ultralytics | 空卡 + warning"缺 ultralytics 依赖（pyproject vision 组）" |
| 缺权重 | 未传 model 且未配置 `SITEGUARD_VISION_MODEL` | 空卡 + warning"未配置视觉模型权重" |
| 推理失败 | 模型/推理异常 | 空卡 + warning"视觉推理失败" |
| 类别未登记 | 检出类别不在受控映射 | 该条丢弃 + warning（其余检出不受影响） |
| 注入检测器异常 | detector 抛错 | 空卡 + warning"注入检测器执行失败" |

demo 层（`demo --with-vision`）：有样例图且依赖/权重可用 → 图文融合报告；无样例图
打印说明跳过、依赖缺按上表降级，两者均 warnings 汇总进报告并 **exit 0**；
默认 `demo`（不带 flag）行为不变。

  外逐字段一致；`eval` 全指标与 M3 持平（F1=1.0000、FP=0、端到端 108/108、误报 0）；
  `datagen --force` 位级一致。
