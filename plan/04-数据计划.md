# 04 数据计划

## 1. 四类数据目录与台账纪律

```
data/
├── samples/          # 领域文档样本：自制巡查记录/施工日志/方案片段
│   ├── text/         #   文本（高处作业、临时用电两大场景优先）
│   └── images/       #   图像（SHWD 抽样，M4 启用）
├── knowledge/        # 法规知识库：regulations 条文块 JSONL / thresholds 阈值表 / seed KG 词表
├── eval/             # 评测资产：gold 真值（生成器产出）/ cases 配对案例
└── README.md         # 数据台账：每个文件登记 来源/许可/日期/脱敏状态
```

**台账纪律**：任何进仓库的数据文件必须登记来源与许可；含真实个人信息的数据一律
不进仓库（本地保留），台账中登记占位。

## 2. 真实项目数据缺失的替代方案（当前状态：未提供）

| 缺失数据 | 替代来源 | 状态 |
| --- | --- | --- |
| 施工日志/巡查记录 | **程序化生成器**（`scripts/make_samples.py`）：模板+受控词表随机组合生成带真值语料，可注入"已知差异"做配对评测 | 骨架期即建 |
| 相关条文规范 | 公开标准条目手工整理（JGJ 59-2011 检查项目框架、JGJ 80-2016 高处作业、JGJ 46 临电、《重大事故隐患判定标准（2022版）》），只录研判所需条目，标注"以官方文本为准" | 骨架期建种子，M2 扩充 |
| 历史隐患记录/整改报告 | 公开事故通报摘要脱敏（住建部/地方住建厅通报），做 Case 节点 | M2~M3 |
| 图像隐患数据 | **SHWD**（njvisionpower/Safety-Helmet-Wearing-Dataset，GitHub，7581 张，VOC 标注，研究用途）+ ModelScope 镜像 `safetyhelmet_dataset` | M4 |
| 视频数据 | 不引入真实视频；用公开演示视频抽帧（P2） | — |

## 3. 程序化生成器设计（核心资产）

- **输入**：受控词表（hazard_types / site_objects / work_types）+ 句式模板库
  （每类隐患 ≥3 种口语化变体，含人称/时间/部位替换）。
- **输出**：`data/samples/text/*.txt` + `data/eval/gold/*.json`（每条文本对应真值
  HazardCard 列表，字段级对齐）。
- **配对评测**：同项目"施工日志 vs 巡查记录"双版本生成，其中一份注入 N 处已知差异
  （漏项/数值不一致），用于端到端检出率/误报率评测。
- **纪律**：生成器是黄金路径——评测脚本只信生成器真值，不信样例文件本身；
  样例文件改动必须由生成器重跑产出，禁止手改。

## 4. 规范条文块 schema（data/knowledge/regulations/*.jsonl）

```json
{"std_id": "JGJ59-2011", "std_name": "建筑施工安全检查标准", "clause": "3.13.3",
 "text": "……", "blocks": ["高处作业"], "keywords": ["安全网", "临边"],
 "note": "种子条目，以官方文本为准"}
```

## 5. 下载与网络 fallback（国内网络）

官方渠道 → npmmirror / hf-mirror / ModelScope / ghproxy 镜像 → raw 直连；
逐文件重试 + 校验（魔数/大小/数量），失败换通道并记台账。
SHWD 下载脚本：`scripts/download_shwd.py`（M4 启用，含 md5 抽查）。

## 6. 数据里程碑

- **M0（骨架）**：目录 + 台账 + 生成器 v1（两大场景各 20 条带真值）+ 种子词表 v1
- **M2**：条文块扩充至 ~80 条；案例 10 条；生成器加口语化变体
- **M4**：SHWD 图像样例接入 + 图文配对真值
